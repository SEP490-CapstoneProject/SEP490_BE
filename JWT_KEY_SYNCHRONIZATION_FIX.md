# JWT Key Synchronization Fix - Complete

## Problem Statement

The Notification service was not matching JWT keys with other services due to inconsistent configuration:

### Issues Found:
1. **Notification Service**: Used `JwtSettings:SecretKey` (wrong Key Vault secret name)
2. **Community & Company Services**: Used `JwtSettings:Secret` but **disabled Issuer/Audience validation**
3. **Auth & UserProfile Services**: Correctly used full validation but different configuration patterns
4. **Inconsistent validation**: Some services validated all JWT fields, others validated only the signature

## Root Cause

Different services were reading different configuration keys from Azure Key Vault:
- `JwtSettings:SecretKey` (Notification only)
- `JwtSettings:Secret` (Community, Company)
- No consistent schema across all services

Additionally, JWT token validation was inconsistent - some services accepted tokens from ANY issuer/audience, while others enforced strict validation.

## Solution Implemented

Standardized all services to use the **shared `JwtSettings` configuration class** from `RecruitmentPlatform.Common`:

```csharp
public class JwtSettings
{
    public string Secret { get; set; } = string.Empty;
    public string Issuer { get; set; } = string.Empty;
    public string Audience { get; set; } = string.Empty;
    public int AccessTokenExpirationMinutes { get; set; } = 60;
    public int RefreshTokenExpirationDays { get; set; } = 7;
}
```

### Configuration Pattern Applied to ALL Services:

```csharp
// Standardized JWT configuration
var jwtSettings = builder.Configuration.GetSection("JwtSettings")
    .Get<JwtSettings>() ?? new JwtSettings
{
    Secret = "default-secret-key-32-characters!",
    Issuer = "SkillSnapAuth",
    Audience = "SkillSnapUsers"
};

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuerSigningKey = true,
            IssuerSigningKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(jwtSettings.Secret)),
            ValidateIssuer = true,
            ValidIssuer = jwtSettings.Issuer,
            ValidateAudience = true,
            ValidAudience = jwtSettings.Audience,
            ValidateLifetime = true
        };
    });
```

## JWT Validation Flow (Now Consistent)

All services now perform the following validation:

1. ✅ **Issuer Signing Key** - Verify token is signed with correct secret
2. ✅ **Issuer** - Verify token was issued by "SkillSnapAuth"
3. ✅ **Audience** - Verify token is intended for "SkillSnapUsers"
4. ✅ **Lifetime** - Verify token hasn't expired

This ensures:
- Tokens generated by Auth service are accepted by all other services
- Invalid tokens are rejected consistently across all services
- Cross-service communication is secure and authenticated
